# 18. URGENT DELIVERY MODE — NOVEMBER 6

The project has an urgent delivery deadline: November 6, 2026, at 10:00 AM.

The priority is to deliver a visually polished and functional Growii frontend.

The development approach must be pragmatic and incremental.

## Working Rules

- Do not perform a lengthy standalone audit.
- Perform only the minimum inspection needed before each change.
- Inspect existing files before replacing them.
- Reuse existing components and functionality whenever possible.
- Work directly on the frontend.
- Do not wait for approval for every small implementation detail.
- Explain the proposed changes briefly and proceed with reasonable, reversible decisions.
- Ask for approval before destructive changes, major architectural changes or new dependencies.
- Do not modify the backend.
- Do not invent API functionality.
- Test each feature immediately after implementing it.

## Delivery Priorities

### Priority 1 — Visual experience

- Welcome screen.
- Growii identity.
- Vertical kiosk layout.
- Typography inspired by Hold.
- Warm off-white, black and orange visual palette.
- Large accessible controls.

### Priority 2 — Navigation

- Student profile.
- Graduate / Alumni profile.
- Company / Recruiter profile.
- Functional navigation between screens.

### Priority 3 — Conversation

- Chat interface.
- Message input.
- Send button.
- Conversation history.
- Loading and error states.
- Existing backend integration, if available.

### Priority 4 — Assistant identity

- Growii owl visual presence.
- Lightweight animations.
- Existing or quickly integrable animated avatar if feasible.

### Priority 5 — Voice

- Only implement if the previous priorities are stable and there is sufficient time.

## Implementation Strategy

Work in short development cycles:

1. Inspect the relevant code.
2. Make the smallest necessary change.
3. Run the frontend.
4. Check the result.
5. Fix errors.
6. Continue to the next feature.

Do not spend excessive time producing documentation.

Keep the developer informed about:

- Files modified.
- Features completed.
- Features still pending.
- Commands needed to test.

The delivery must prioritize a working, coherent and visually polished product over an excessive number of incomplete features.

Never claim something works unless it has been tested.
